# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Swedish/English voice assistant for a Raspberry Pi 5: an offline wake phrase ("Hey Gemini" / "Hey Assistant") opens a Gemini Live conversation, which closes after 8 s without speech and returns to idle. The authoritative spec is `_bmad-output/specs/spec-gemini-voice-assistant/` (`SPEC.md`, `stack.md`, `pi-setup.md`, `stories.yaml`; `.memlog.md` is the canonical decision log the SPEC is derived from). `docs/plan.md` (Swedish) is the original plan; its code is superseded and wrong for the current SDK.

Code is written on the Windows PC in `src/` and **runs on the Pi** (`gemini-pi.local`, user `allramest`, project dir `~/gemini-assistant` with a venv at `venv/`). Audio libraries and the Vosk model live only on the Pi.

## Working on the Pi

Claude's dedicated key is `~/.ssh/id_ed25519_claude` (no passphrase; the Pi's `authorized_keys` line ends `claude-code@kaywi-pc`):

```
SSHO="-i $HOME/.ssh/id_ed25519_claude -o IdentitiesOnly=yes -o BatchMode=yes"
scp $SSHO -r -q src/. gemini-pi:gemini-assistant/        # deploy (never contains .env)
ssh $SSHO gemini-pi 'cd ~/gemini-assistant && ./venv/bin/python -m pytest -m "not integration" -q'
ssh $SSHO gemini-pi 'cd ~/gemini-assistant && ./venv/bin/python -m pytest -m integration -q'   # network + API key + fixtures
ssh $SSHO gemini-pi 'cd ~/gemini-assistant && ./venv/bin/python -m assistant --simulate /tmp/sim_in.wav'   # end-to-end, wav as mic
```

- Single test: `... -m pytest tests/test_session_fake.py::test_barge_in_clears_playback -q`.
- Real devices: `python -m assistant --list-devices`, then `python -m assistant`.
- Spoken fixtures (`tests/fixtures/*.wav`) are generated by `tools/make_fixtures.py` using Gemini Live itself, so they are a proxy for a human voice.
- The Pi's `.env` holds `GEMINI_API_KEY` (chmod 600). Never print it: `Config.gemini_api_key` is `repr=False`; redact tool output (`sed -E "s/AQ\.[A-Za-z0-9_-]+/<key>/g"`) when running anything that might echo it.

## Architecture (src/assistant/)

- `app.py` — loop: `wait_for_wake` (blocking mic frames into the detector) -> chime -> `asyncio.run(LiveConversation.run())`. A new event loop and client per conversation. One mic object lives for the whole process; the wake stage and the session read it one at a time (the session's mic thread is joined before returning to idle).
- `wake.py` — Vosk `KaldiRecognizer` restricted to a phrase grammar plus `[unk]`, with the small English model. Words must exist in the model vocabulary ("gemini", "assistant" do; "gimini" does not). No vendor account or key.
- `session.py` — `LiveConversation`: mic thread -> `asyncio.Queue` -> `send_realtime_input`; `_receive` loops over `session.receive()` (which ends after each turn); `_monitor` ends the session via `IdleTimer`. `IdleTimer` resets on speech from either party and keeps resetting while the speaker is still playing.
- `audio.py` — `PyAudioMic`/`PyAudioSpeaker` (speaker plays 50 ms pieces so `clear()` implements barge-in) and `FakeMic`/`FakeSpeaker` used by tests and `--simulate`.
- `config.py` — constants (16 kHz in, 24 kHz out, 8 s idle) and `.env`-driven `Config`.

## Gemini Live gotchas (verified with google-genai 3.0.0)

- Model `gemini-3.8-live` (not in `models.list()`); the SDK's default API version returns HTTP 404, so `api_version` must be `v1beta` (or `v1alpha`).
- Input is `audio/pcm;rate=16000` via `send_realtime_input(audio=types.Blob(...))`; output is 24 kHz PCM16. Interruptions arrive as `server_content.interrupted`. Audio-only sessions are capped at 15 minutes.
- A transient `1008 ... does not have permission` appeared once right after billing was enabled, then went away.
