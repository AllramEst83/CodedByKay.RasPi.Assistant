- (decision) Why = vision/opportunity: hands-free, voice-only Gemini assistant on owned hardware; local wake word keeps audio off the network until activated (privacy).
- (capability) CAP-1 Idle listening: device listens only locally for the wake word 'Hey Gemini' with no network audio traffic. Success: with network capture running, zero audio egress while idle; wake word triggers on a normal-voice utterance at ~2m.
- (capability) CAP-2 Activation feedback: on wake word the user hears a confirmation chime before the live session opens. Success: chime audible on each detection, generated in code (no asset files).
- (capability) CAP-3 Live voice conversation: after activation user speaks and hears Gemini's spoken reply in real time (16kHz PCM up, 24kHz PCM down). Success: spoken question answered aloud with first audio within ~2s of end of speech on home broadband.
- (capability) CAP-4 Barge-in: user can interrupt the assistant mid-reply. Success: speaking over a reply stops playback and the new utterance is handled.
- (capability) CAP-5 Follow-up and auto-sleep: follow-ups need no wake word while the session is active; after a silence timeout the session closes and device returns to idle. Success: follow-up within timeout works without wake word; after timeout log shows session closed and wake word required again.
- (capability) CAP-6 Spoken-style persona: replies are short (1-3 sentences), natural, markdown-free, Swedish by default, English if user speaks English. Success: sampled replies contain no markdown and respect language rule.
- (capability) CAP-7 Headless operation and setup: device is configured and operated entirely over SSH from the Windows PC (PuTTY) with no monitor/keyboard; secrets via chmod-600 .env. Success: fresh-flashed Pi reaches a running assistant using only SSH.
- (capability) CAP-8 Clean reset: Pi can be returned to a known-clean state, discarding the old Docker web-server setup. Success: after reflash no Docker/containers/old user data remain and Pi boots to SSH-reachable fresh OS.
- (decision) Headless SSH via PuTTY is a good approach; Windows 11 built-in OpenSSH (ssh pi@host) is equal alternative. Pi is NOT connected to the PC by a port: it joins the same router/LAN via Ethernet (RJ45) or Wi-Fi; PC reaches it by hostname.local or router-assigned IP.
- (decision) Reset = reflash microSD with Raspberry Pi Imager (Raspberry Pi OS Lite 64-bit, Bookworm or later); use Imager OS customisation to set hostname, user, password, Wi-Fi, SSH. Needs a microSD reader on the PC. Back up anything wanted from old Docker setup first; reflash erases the card.

- (constraint) Pi 5 power: official 27W USB-C PSU (5V/5A) recommended; USB audio devices draw from USB ports and underpowered supply caps USB current.
- (constraint) Wake word needs a custom Picovoice Porcupine .ppn for 'Hey Gemini' (Raspberry Pi platform) and a Picovoice AccessKey; free tier is personal/non-commercial.
- (constraint) Mic is held by one consumer at a time: Porcupine stream closed before Live session opens and vice versa. Both need 16kHz mono 16-bit PCM input.
- (constraint) Network required only during active session; Gemini API key and Picovoice key live in .env on the Pi, never committed.
- (constraint) Default Pi login 'pi' is not preset in modern Raspberry Pi OS; username is whatever is set in Imager. plan.md paths (/home/pi/...) and pscp target must match chosen username.
